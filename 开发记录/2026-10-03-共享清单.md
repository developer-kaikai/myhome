# 日期餐次与共享清单开发记录

日期：2026-10-03。继续按“菜单 → 共享点餐 → 完成评价 → 聚会”的依赖顺序开发。

## 已实现

- ordering 按 Controller / Service / Repository / DTO 拆分共享草稿；服务端提供今天/明天及凌晨昨日宵夜，截止时刻拒绝普通写入。
- MySQL 持久化清单；读取不创建数据，两个用户同时创建只得到一个餐次聚合。已完成餐次占用，取消后要求明确重建，当前不自动开新单。
- 同菜、同规格、同原添加人合并数量；跨人或跨规格分行。维度单选，服务端按所选日期月份核验供应、上下架、菜品版本及选项有效性。
- 日常协作者可增减、修改及移除任一行，原添加人不变；数量1—99、最多100行，减至零软移除。清空有二次确认与版本校验，规格冲突不覆盖他人变化。
- 当前采用数据库餐厅行锁 → 餐单行锁 → 明细当前读，菜单当前读与 core 维护保持一致；写入和审计、幂等响应在同一事务。Redis 不存放清单事实。
- 小程序接入餐厅切换、日期/餐次选择、默认规格抽屉、已选清单、原点餐人及道数/份数/点菜人数。前台每2秒同步，隐藏停止；迟到请求不覆盖新餐厅或更新后的快照。
- 网络结果不明保留原操作键，核对后再重试；规格冲突保留输入并展示最新规格和份数。日常资格失效后保留编辑，重新验证后需主动核对重试。
- V4 增量扩展餐单名称与昵称快照容量，保留中文备注和20可见字符业务上限；未修改旧迁移。顾客菜单现在隐藏所有没有有效菜品的品类。
