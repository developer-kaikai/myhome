# 正式下单与餐单管理开发记录

日期：2026-10-03。承接日期餐次与共享清单，完成“复核 → 正式提交 → 追加/修改 → 取消/明确重建”的日常餐单流程。

## 已实现

- ordering 新增提交复核、首次/追加提交、人数备注、取消重建、分页列表与详情接口。首次提交直接进行中，无接单审批；发起人仅首次生成，编号不随追加变化。
- 正式行与待提交追加行分开；只提交有效待提交行，已提交份数不重复累计。原添加人保持，原点单者资格不因删菜抹除；只有代改/代提交的协作者不自动成为评价提醒收件人。
- 提交前复核最新聚合版本、菜品版本指纹、月份/上下架和规格。失效行在确认页标红，其他选择保留；他人变更展示差异并需重新核对。人数1—20，备注/取消原因最多100个可见字符。
- MySQL 餐厅 → 餐单 → 明细锁与唯一约束、事务幂等共同保护提交。待提交归并后每行最多99份、正式单最多100行，越界整笔回滚。锁后复核使用当前读，避免等待期间沿用旧快照。
- 日常协作者可修改全部菜品；人数备注仅主厨或发起人可改，整单取消仅本店主厨或发起人。删最后一行须明确取消，普通协作者不能删空正式单。
- 当前开放进行中餐单可由日常协作者发现；截止后和历史只向本店主厨或参与者开放，普通访客还须有效日常资格。主厨工作台新增本店过滤入口。取消单保留所有行，明确重建只创建空草稿，不自动复制/复活原单。
- Outbox、参与者与审计在业务事务落库；首次立即生成下单任务，追加/正式修改从首事件起固定30秒合并，取消撤销旧任务并排除操作者。每60秒补查到点仍进行中的单，每单只生成一次确认事件，不自动完成或计次。
- V5 新增私房做法提交快照，普通DTO不包含，仅本店主厨专用接口读取。备注和原因扩展物理存储，保留100可见字符上限及中文备注，V1—V4未修改。
- 原生小程序接入提交确认、人数备注/口味标签、版本差异复核、超时同键核对重试、列表过滤、正式详情、修改人数备注、取消原因与二次确认、明确重新点餐，以及主厨查看提交时做法。
