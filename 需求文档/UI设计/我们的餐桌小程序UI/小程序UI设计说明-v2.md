## 2. 视觉方向

### 2.1 设计原则

1. **先让人想吃饭**：首页和菜单使用真实、自然光下的家常菜图片，统计信息退居次要层级。
2. **一次只强调一个动作**：每屏只保留一个实心主按钮，其余操作使用描边按钮或文字入口。
3. **像两个人的餐桌**：用双杯、双碗、蒸汽、叶子和手写小批注增加亲密感，避免商业餐饮促销视觉。
4. **减少后台感**：弱化大面积边框和均匀宫格，用留白、字号、图片和浅色分区建立层级。
5. **状态靠文字说清楚**：进行中、仅主厨可见、补充中、7 天有效等状态同时显示文字，不只依赖颜色。

### 2.2 色彩建议

| 用途 | 色值 | 使用方式 |
| --- | --- | --- |
| 页面底色 | `#F7F3EA` | 暖米白，所有主页面背景 |
| 内容卡片 | `#FFFDF8` | 菜品、订单、聚会及个人信息卡片 |
| 主文字 | `#1F211D` | 标题、金额和关键数据 |
| 次文字 | `#777970` | 说明、日期、参与者等辅助信息 |
| 鼠尾草绿 | `#77966D` | 主按钮、选中态、成功状态，避免全屏泛绿 |
| 番茄红 | `#E6644A` | 喜爱、提醒和少量情绪强调 |
| 黄油黄 | `#F2C96D` | 待确认、补充中、提示条 |
| 分割线 | `#E7E2D8` | 1px 细线和输入边界 |

颜色对比度需在开发稿中按正文和大字分别检查，不能只以效果图观感作为无障碍验收结果。

### 2.3 字体与间距建议

- 使用微信环境可用的系统中文无衬线字体；标题字重 600—700，正文 400—500。
- 页面主标题建议 28—32px，模块标题 18—20px，正文 14—16px，辅助信息不小于 12px。
- 页面左右安全边距 20px；卡片圆角 18—20px；主按钮高度 48—52px。
- 卡片主要依靠底色和留白分层，只使用极浅阴影，避免每个模块都有厚重描边。

## 3. 页面设计要点

| 页面 | 核心内容 | 主操作 | 需求约束 |
| --- | --- | --- | --- |
| 首页 | 今晚问候、时令菜、做饭次数、最受欢迎、趋势 | 去点餐 | 首先呈现食物和邀请感，统计保持紧凑 |
| 选择餐厅 | 两张大图餐厅卡、主厨、今天/明天 | 选择餐厅 | 固定双餐厅，不做商家列表 |
| 点餐 | 日期餐次、左侧品类、菜品、已选摘要 | 查看清单 | 日常菜品不显示价格、支付或结算 |
| 菜品详情 | 大图、简介、评分、规格、数量 | 加入清单 | 不显示价格；做法不向顾客展示 |
| 进行中餐单 | 餐次、参与者、菜品及贡献者、同步状态 | 修改餐单 | 所有协作者可改菜；主厨无需接单 |
| 确认这顿饭 | 实际菜品勾选、本店菜单补菜 | 确认完成 | 仅本店主厨可见；菜单没有的菜不补录 |
| 评价邀请 | 实际菜品、星级、短评、进度、截止日期 | 提交评价 | 评价不区分角色，记录评价人 |
| 好友评价落地 | 餐厅、餐次、实际菜品、登录说明 | 微信登录并评价 | 无需日常密令；自动注册；7 天内有效 |
| 聚会详情 | 主题、时间地点、成员、采购、人均参考 | 添加采购 | 聚会金额与日常点餐分离 |
| 聚会重开 | 补充中提示、补报名、补采购 | 再次结束聚会 | 重开期间允许补报名和补充采购 |
| 我的 | 昵称、当前餐单、历史、评价、聚会、通知 | 进入主厨工作台 | 昵称可修改；只有主厨显示工作台入口 |
| 主厨工作台 | 待确认餐单、今日概览、菜单与密令维护 | 确认这顿饭 | 不显示接单按钮，只管理本店 |

## 4. 组件与交互统一

- 底部导航固定为“首页、点餐、订单、聚会、我的”；聚会邀请和好友评价受限页不展示日常导航。
- 实心绿色按钮表示当前页面唯一主操作；描边按钮表示追加、修改、分享等可选操作。
- 状态色同时配文字：绿色用于完成/进行中，黄色用于待确认/补充中，红色只用于取消或高风险提醒。
- 点餐页底部已选栏固定悬浮，展示“道数 + 份数”，不出现购物车、金额或结算文案。
- 订单完成确认用勾选列表表达“实际做了什么”；删除没做的菜无需另开流程。
- 菜品和聚会图片统一使用自然光、真实材质，避免过度饱和、棚拍广告感和商业促销贴纸。
