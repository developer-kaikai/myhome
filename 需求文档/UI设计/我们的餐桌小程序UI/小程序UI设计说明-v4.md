# “我们的餐桌”小程序 UI 设计说明 v4

| 项目 | 内容 |
| --- | --- |
| 需求基线 | 《我们的餐桌功能需求说明书》v1.5 |
| 设计版本 | v4（推倒重做） |
| 设计日期 | 2026-09-10 |
| 设计主题 | 餐桌编辑部：明快、直接、有参与感的家庭美食记录 |
| 开发基线 | v4 两张 UI 总览与本说明；v2、v3 仅用于历史比较 |

## 1. 最终设计稿

- `小程序UI总览-v4-日常点餐.png`：首页、选择餐厅、点餐、菜品详情、进行中餐单、确认这顿饭。
- `小程序UI总览-v4-评价聚会管理.png`：评价邀请、好友评价落地、聚会详情、聚会补充中、我的、主厨工作台。

两张总览用于确定视觉方向、信息层级和主要状态。图片中的小字号内容属于示意，开发时以需求文档和本说明中的文字、权限及状态为准。

## 2. 为什么重做

v3 的功能覆盖完整，但奶油底、陶土色、宋体标题、卡片和手绘装饰同时出现，页面容易显得复古、厚重。多数信息被装进相似卡片，主要动作、状态信息与情绪内容缺少明显主次，首页和管理页也容易呈现为同一种仪表盘。

v4 保留全部业务规则，重新建立三个层级：

1. **先看今天要做什么**：每页只保留一个最醒目的标题和一个主要动作。
2. **再看和谁一起**：人物头像、点餐人和参与人数进入主要信息区，不再作为边角元数据。
3. **最后处理细节**：统计、状态、规格、采购金额和管理入口按场景收拢，避免所有内容同时抢眼。

## 3. 视觉方向

### 3.1 关键词

明快、松弛、现代、好吃、有人情味。温度主要来自食物摄影、人物头像、真实文案和共同参与关系，不依赖复古配色或大量装饰。

### 3.2 色彩 Token

| Token | 色值 | 用途 |
| --- | --- | --- |
| `--color-page` | `#FFFDF7` | 页面底色 |
| `--color-ink` | `#1C1C18` | 标题、正文、黑色主按钮 |
| `--color-lime` | `#DDF44B` | 主按钮、当前 Tab、选中态、进度条 |
| `--color-lime-pressed` | `#C8DF34` | 主操作按下态 |
| `--color-coral` | `#FF6B4A` | 待处理、危险提示和少量提醒 |
| `--color-surface` | `#F2F2EC` | 次级信息区、输入框、弱卡片 |
| `--color-line` | `#DFDFD8` | 分割线和默认描边 |
| `--color-muted` | `#73736D` | 日期、说明和辅助信息 |
| `--color-white` | `#FFFFFF` | 图片上的文字、局部内容面 |

色彩遵循“一页一块青柠黄”的规则。青柠黄只标记当前选择或主操作；警告色只出现在确实需要处理的状态，聚会费用不额外引入金色。成功状态以图标和文字表达，可使用青柠黄浅底，不另建大面积绿色体系。

### 3.3 字体与字号

全局使用现代中文无衬线字体。小程序首版不下载网络字体，按 `PingFang SC, MiSans, HarmonyOS Sans SC, Microsoft YaHei, sans-serif` 回退。标题通过字号、字重和紧凑行距建立性格，不再混用宋体。

| 层级 | 建议值 | 规则 |
| --- | --- | --- |
| 首屏主标题 | 32px / 1.12 / 700—800 | 一页最多一处，最多两行 |
| 页面标题 | 26px / 1.2 / 700 | 列表、详情和管理页使用 |
| 模块标题 | 18px / 1.35 / 600 | 与正文至少相差两级 |
| 主要正文 | 15—16px / 1.5 / 400 | 菜名可使用 600 |
| 辅助文字 | 12—13px / 1.4 / 400 | 颜色使用 `--color-muted` |
| 主按钮 | 16px / 1 / 600 | 不使用强制字间距 |
| 关键数字 | 28—32px / 1 / 700 | 使用等宽数字特性 |

中文不使用斜体，不以连续空格制造字距，不使用手写体承载关键业务文字。手写线条只可作为不影响阅读的少量情绪装饰。

## 4. 布局体系

- 设计基准宽度为 375px，页面左右安全边距 16px，主要模块间距 20—24px。
- 采用 4px 基础网格，常用间距为 8、12、16、20、24、32px。
- 页面不再默认“每一块内容一个卡片”。同一语义组优先用留白和 1px 分割线组织。
- 图片是首屏重点时采用 16:9 或 4:3；列表缩略图统一 72×72px，圆角 12px。
- 卡片圆角 16—20px，按钮圆角 14px 或胶囊形；同一组件保持统一。
- 只在浮层、吸底操作条与图片叠层使用轻阴影，其余内容面保持扁平。
- 页面底部为五个固定 Tab：`首页 / 点餐 / 餐单 / 聚会 / 我的`。当前项使用青柠黄小胶囊，不能只依赖颜色区分。

## 5. 核心组件

### 5.1 主按钮

青柠黄底、墨黑文字，高 48px，整行或内容区宽度。每个视口内最多出现一个青柠黄主按钮。需要强结束语义的“再次结束聚会”使用墨黑底白字，避免与普通新增操作混淆。

### 5.2 次按钮与危险操作

次按钮使用透明或白底、1px 墨黑描边。危险操作使用珊瑚橙文字；只有二次确认弹窗中的最终危险操作可以使用珊瑚橙实心按钮。

### 5.3 状态标签

状态标签必须同时显示文字，统一为小号胶囊：

- `进行中`、`补充中`：青柠黄底、墨黑字。
- `待确认`、`待认领`：浅珊瑚底、珊瑚深色字。
- `已完成`、`已购买`、`已结束`：浅灰底、墨黑字，并配合勾选图标。
- `仅主厨可见`：浅珊瑚底，不使用锁图标代替文字。

### 5.4 人物参与条

头像直径 28—36px，最多展示 5 个，超出显示 `+N`。点餐列表和餐单明细必须保留昵称或“由谁点的”，头像不能成为唯一身份信息。

### 5.5 食物图片

采用自然光、近距离、真实餐桌质感，避免商业海报式摆拍、复杂文字贴图和过度饱和滤镜。菜单列表使用统一比例；无图时使用简洁餐盘线稿占位，不能随机放置无关食物图片。

## 6. 十二个核心页面

### 6.1 首页

首页首屏回答“今晚吃什么”。问候和大标题后依次展示今日推荐、`开始点餐`、本周两项摘要和最近聚会。统计只展示 `本周做饭` 与 `最受欢迎`，完整周/月/年切换进入统计详情，避免首屏出现图表面板。

### 6.2 选择餐厅

日期切换放在标题下方，两家餐厅使用大图卡片纵向排列。餐厅名、主厨头像和名称必须在卡片上直接可见，点击整张卡片进入菜单，不额外增加多个入口。

### 6.3 点餐

餐次横向排列，当前餐次使用底部青柠色短线。左侧品类保持窄栏，右侧列表突出菜图、菜名、评分和加号。吸底条只显示已选道数、份数和 `查看清单`，不使用购物车图标及价格语言。

### 6.4 菜品详情

食物图片占上半屏，信息区仅保留菜名、评分、简介、规格、数量和 `加入清单`。评价列表从信息区继续向下滚动，不在首屏塞入多张评价卡片。

### 6.5 进行中餐单

标题、状态、日期餐次和参与人位于同一首屏信息组。菜品用紧凑行展示份数及原点餐人。`追加菜品` 与 `修改餐单` 为并列次操作，主厨同步提示使用弱信息条，不模拟接单状态。

### 6.6 确认这顿饭

突出“勾选实际做过的菜”。默认带出正式餐单，未选行降低对比度；`从本店菜单补一道` 使用描边行。`确认完成` 为唯一主按钮，`这顿没做` 为低频危险文字操作。

### 6.7 评价邀请

每道菜采用图片、菜名、星级和一行评论输入，不使用嵌套大卡片。进度与截止时间固定显示在标题区；`邀请朋友评价` 为次按钮，`提交评价` 为主按钮。

### 6.8 好友评价落地

先展示这桌真实做过的菜和聚餐氛围，再解释登录用途。未登录状态不展示完整订单细节；主按钮文案为 `微信登录并评价`，并明确 `无需日常密令 · 7天内有效`。

### 6.9 聚会详情

主题图、时间地点和报名头像形成一个连续的活动头部。采购清单用列表组织，费用汇总固定在主操作上方。金额仅出现在聚会模块，`添加采购` 为主操作。

### 6.10 聚会补充中

沿用聚会详情结构，在标题旁增加 `补充中`，顶部展示重开说明。`分享邀请`、`补充采购` 为次操作；`再次结束聚会` 使用墨黑主按钮。

### 6.11 我的

头像、昵称编辑和一句产品文案构成轻量页头。进行中餐单优先展示，其次为历史餐单、我的评价、聚会记录、通知设置。主厨才看到 `我的厨房` 入口；访客页面不保留空的后台位置。

### 6.12 主厨工作台

这是小程序内的移动管理页，不做桌面后台式侧栏。首屏优先展示待确认餐单和 `确认这顿饭`；餐厅设置、菜单品类、菜品管理、准入密令使用四宫格快捷入口；最近聚会置于其后。统计卡只保留进行中和今日完成两个数字。

## 7. 动效与反馈

- 加减菜、餐次切换、标签选中使用 160—220ms 的缩放或位移动效。
- 加入清单成功时，加号短暂变为勾选并更新吸底条，不播放大面积庆祝动画。
- 跨设备同步后，在受影响条目旁显示 2 秒轻提示；发生冲突时使用明确文案要求重新核对。
- 页面骨架屏遵循最终布局，不使用通用整页灰块。
- 图片加载失败不影响加菜、报名、评价等主要操作。

## 8. 适配与可访问性

- 所有点击目标不小于 44×44px；正文不小于 14px，辅助文字不小于 12px。
- 青柠黄上的正文必须使用墨黑，不使用白字；文字与背景对比度按 WCAG AA 校验。
- 星级、状态、选择和错误不能只以颜色表达，须同时使用图标、形状或文字。
- 昵称按 8 个中文字符的常用宽度设计，超出省略；完整昵称在详情或轻提示中查看。
- 适配顶部微信胶囊、底部安全区和键盘弹出；吸底按钮不得遮挡最后一行内容。
- 小屏时采购项允许分两行，金额和操作不能被截断。

## 9. 开发交接规则

1. 先实现设计 Token、字体、按钮、状态标签、人物参与条、菜品行、吸底操作条和底部导航，再组装页面。
2. 首页、点餐、餐单、聚会和我的五个 Tab 共用统一导航组件；评价分享和聚会邀请落地页按权限隐藏无关 Tab。
3. 页面文案、权限、状态和数据范围以 v1.5 需求文档为准，视觉稿不新增业务状态。
4. 图片使用可替换资源位；开发演示数据不得写入正式接口或生产初始化脚本。
5. 375px、320px 和 430px 三档宽度完成视觉回归，并在微信开发者工具及至少一台真机验证顶部胶囊、底部安全区、滚动和键盘遮挡。

## 10. 本版不延续的视觉做法

- 不再使用奶油纸张加陶土红的复古配色。
- 不再混用宋体标题和黑体正文。
- 不再给每段信息套独立阴影卡片。
- 不再用植物枝叶作为通用页面装饰。
- 不再让手写批注靠近按钮、金额、状态和输入等关键内容。
- 不再把首页设计成统计图表面板，也不把主厨工作台设计成桌面管理后台。
